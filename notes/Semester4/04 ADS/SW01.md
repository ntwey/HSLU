## 2. Analyse von Algorithmen

Ein **Algorithmus** ist eine schrittweise Anweisung zum Lösen eines Problems in endlicher Zeit.

### Relevante primitive Operationen
Zur Bestimmung der theoretischen Laufzeit werden atomare Rechenschritte gezählt:
- Evaluation eines Ausdrucks
- Zuweisung eines Wertes an eine Variable
- Indexieren eines Arrays (`A[i]`)
- Aufruf einer Methode / Funktion
- Verlassen einer Methode (`return`)

### Beispiel: Maximumsuche im Array (`arrayMax`)
- **Worst-Case:** Wenn das Array aufsteigend sortiert ist und `currentMax` bei jedem Schritt überschrieben werden muss:
  $$T_{\text{worst}}(n) = 8n - 2 \in \mathcal{O}(n)$$
- **Best-Case:** Wenn das Maximum direkt an Index 0 liegt:
  $$T_{\text{best}}(n) = 6n \in \mathcal{O}(n)$$

## 3. Asymptotische Analyse & Big-O-Notation

### Asymptotisches Verhalten
- Bei sehr grossen Eingaben ($n \to \infty$) spielen **konstante Faktoren** und **niedrigere Potenzen** keine Rolle.
- Die höchste Potenz dominiert:
  - $10^2 n + 10^5 \in \mathcal{O}(n)$ (linear)
  - $10^5 n^2 + 10^8 n \in \mathcal{O}(n^2)$ (quadratisch)

### Mathematische Definition der O-Notation
Eine Funktion $f(n)$ ist $\mathcal{O}(g(n))$, wenn es eine positive Konstante $c > 0$ und eine Schranke $n_0 \ge 1$ gibt, sodass gilt:
$$f(n) \le c \cdot g(n) \quad \text{für alle } n \ge n_0$$

*Beispiel:*
$$2n + 10 \le 3n \quad \text{für } n \ge 10 \implies 2n + 10 \in \mathcal{O}(n) \quad (c=3, n_0=10)$$

## 4. Typische Schleifenmuster & Arithmetische Progression

### Präfix-Durchschnitte (`prefixAverages1`)
Berechnung des gleitenden Durchschnitts der ersten $i$ Elemente:
$$A[i] = \frac{1}{i+1} \sum_{k=0}^{i} X[k]$$

Wird die Summe für jedes $i$ in einer inneren Schleife erneut von 0 aufsummiert, entsteht eine arithmetische Reihe:
$$\sum_{i=1}^{n} i = \frac{n(n+1)}{2} = \frac{n^2}{2} + \frac{n}{2} \in \mathcal{O}(n^2)$$

> [!NOTE] Verschachtelte Schleifen
> Wann immer die innere Schleife abhängig von der Zählvariable der äusseren Schleife $1, 2, 3, \dots, n$ Durchläufe macht, führt dies über die **Gausssche Summenformel** zu einer quadratischen Laufzeit $\mathcal{O}(n^2)$.

## 5. Elementare Sortierverfahren

### 5.1 Selection-Sort (Sortieren durch Auswählen)
1. Alle $n$ Elemente werden in eine unsortierte Sequenz eingefügt: $\mathcal{O}(n)$.
2. Schrittweise wird das kleinste Element der Restsequenz gesucht und entnommen:
   $$n + (n-1) + (n-2) + \dots + 1 = \sum_{i=1}^n i \in \mathcal{O}(n^2)$$
- **Gesamtlaufzeit:** $\mathcal{O}(n^2)$

### 5.2 Insertion-Sort (Sortieren durch Einfügen)
1. Jedes neue Element wird direkt an der korrekten Stelle in eine sortierte Sequenz einsortiert:
   $$1 + 2 + \dots + n = \sum_{i=1}^n i \in \mathcal{O}(n^2)$$
2. Entnahme aller Elemente aus der sortierten Sequenz: $\mathcal{O}(n)$.
- **Gesamtlaufzeit:** $\mathcal{O}(n^2)$

### 5.3 In-Place Insertion-Sort
Verhindert zusätzlichen Speicheraufwand:
- Das übergebene Array wird virtuell unterteilt:
  - **Links:** Sortierter Teil (initial Länge 1 mit Element an Index 0).
  - **Rechts:** Unsortierter Rest.
- Das jeweils nächste Element (`cur`) aus dem unsortierten Teil wird zwischengespeichert.
- Grössere Elemente links davon werden nach rechts verschoben (`move`), bis die Einfügeposition frei ist, worauf `cur` eingesetzt wird.

## 6. Rekursion vs. Iteration

| Eigenschaft | Iteration | Rekursion |
| :--- | :--- | :--- |
| **Mechanismus** | Schleifenkonstrukte (`for`, `while`) | Selbstaufruf von Funktionen/Methoden |
| **Steuerung** | Schleifenbedingung / Zähler | Basisfall (Abbruchbedingung) |
| **Arten** | Einfach, geschachtelt | **Direkt:** $A \to A$<br>**Indirekt:** $A \to B \to A$ |

### Basisfall (Verankerung)
Jede Rekursion zwingend benötigt einen Basisfall (*Base Case*), da es andernfalls zu einem unendlichen Aufruf (*Stack Overflow*) kommt.

### Beispiel: Fakultät ($n!$)
Mathematische Definition:
$$f(n) = \begin{cases} 1 & \text{falls } n = 0 \text{ (Basisfall)} \\ n \cdot f(n-1) & \text{falls } n > 0 \text{ (Rekursionsschritt)} \end{cases}$$

#### Implementierung

```java
// Java
static int factorial(int n) {
    if (n == 0) {
        return 1;
    } else {
        return n * factorial(n - 1);
    }
}
```

```python
# Python
def factorial(n):
    if n == 0:
        return 1
    else:
        return n * factorial(n - 1)
```

## 7. Wichtigste Key Takeaways

- **Big-O abstrahiert Hardware-Details:** Konstante Faktoren und Terme niederer Ordnung fallen bei $n \to \infty$ weg; ausschlaggebend ist das asymptotische Wachstum der höchsten Potenz.
- **Arithmetische Summe = Quadratische Laufzeit:** Verschachtelte Schleifen, deren innerer Durchlauf von der äusseren Zählvariablen abhängt ($\sum_{i=1}^n i = \frac{n(n+1)}{2}$), führen zu $\mathcal{O}(n^2)$ (z. B. naiver Prefix-Average, Selection-Sort, Insertion-Sort).
- **In-Place spart Speicher:** In-Place Insertion-Sort partitioniert das Original-Array direkt in einen sortierten und einen unsortierten Teil und benötigt keinen zusätzlichen Hilfsspeicher.
- **Rekursion braucht immer einen Base Case:** Ohne eine klar definierte Abbruchbedingung terminiert die Rekursion nicht und bricht mit einem Stack-Überlauf ab.
