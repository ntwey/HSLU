# 🐳 Docker Introduction - Laborübung Zusammenfassung

## 1. Grundlagen & Vorbereitung
* **Befehlsstruktur**: Docker-Befehle folgen standardmäßig dem Muster:
  `docker <Für was> <Was tun> <Flags> <Image, Name, ID>` (z. B. `docker container run --name mein-nginx nginx`).
* **Docker Image**: Ein unveränderbares Paket/Template (Blueprint) für einen Container, das die Applikation und alle Abhängigkeiten enthält. Es besteht aus verschiedenen wiederverwendbaren Layers, von denen nur der oberste beschreibbar ist (Read-Write).
* **Docker Container**: Die aktive, laufende Instanz, die aus einem Image erzeugt wird.
* **Docker Registry**: Öffentliche oder private Repositories (z. B. Docker Hub, GitHub Container Registry `ghcr`), auf denen Images gespeichert und geteilt werden.
* **Unterschied zu VMs**: Container teilen sich den Kernel des Host-Betriebssystems und benötigen kein eigenes OS. Sie sind daher leichtgewichtiger, kompakter, verbrauchen weniger Speicher/Memory und starten deutlich schneller als Virtuelle Maschinen (die über einen Hypervisor gesteuert werden).
* **Best Practice**: Ein Container sollte grundsätzlich **nur eine Applikation** ausführen, um die Wartbarkeit hoch und die Komplexität niedrig zu halten.

## 2. Dockerfile & Image-Architektur
Ein Dockerfile ist der Bauplan für ein Image und wird strikt von oben nach unten abgearbeitet. Es wird in drei Kernbereiche unterteilt:

### 📑 Die drei Bereiche eines Dockerfiles
1. **Fundamental Instructions**:
   * `FROM`: Definiert das Basis-Image (z. B. `FROM alpine:latest`).
   * `ARG`: Erstellt Variablen, die während des Build-Prozesses genutzt werden können.
2. **Configuration Instructions**:
   * `RUN`: Führt Befehle während des Image-Builds aus (erstellt einen neuen Layer).
   * `COPY` / `ADD`: Kopiert Dateien/Ordner vom Host in den Container.
   * `ENV`: Setzt Umgebungsvariablen, die die Applikation im Container auslesen kann.
   * `WORKDIR`: Setzt das relative Arbeitsverzeichnis im Container für alle nachfolgenden Befehle.
3. **Execution Instructions**:
   * `CMD`: Definiert den Standardbefehl beim Start des Containers. Wird ignoriert, wenn beim `docker run` ein anderer Befehl mitgegeben wird.
   * `ENTRYPOINT`: Definiert den Hauptbefehl, der *immer* ausgeführt wird. Kann mit `CMD` kombiniert werden, um Standardparameter zu übergeben.
   * `EXPOSE`: Dient reinen Dokumentationszwecken und zeigt an, welche Ports der Container öffnet.

> [!WARNING] Wichtiger Caching-Hinweis bei `RUN`
> Befehle wie `apt-get update` und `apt-get install` sollten immer in **einer einzigen** `RUN`-Instruktion mittels `&&` verkettet werden (z. B. `RUN apt-get update && apt-get install -y curl`). Trennt man sie auf, wird das Update aus dem Cache gelesen, was bei späteren Änderungen zu veralteten oder nicht installierbaren Paketen führt.

## 3. Docker-Networking (Netzwerke)
Um Container voneinander zu isolieren oder miteinander kommunizieren zu lassen, stellt Docker verschiedene Netzwerktreiber bereit:

### 🌐 Die wichtigsten Netzwerktreiber
* **Default bridge**: Das Standardnetzwerk. Container können sich hier standardmäßig **nur über die IP-Adresse** anpingen. Es findet *keine* automatische Namensauflösung (Service Discovery) statt.
* **User-defined bridge**: Manuell erstellte Bridge-Netzwerke (z. B. `docker network create mein-netz`). Container im selben benutzerdefinierten Netzwerk können sich automatisch **über ihren Containernamen** erreichen.
* **Host-Netzwerk**: Bindet den Container direkt an das Netzwerk des Hosts. Der Container nutzt die Ports des Hosts, als wäre die Applikation nativ installiert (kein separates `veth`-Interface).
* *Weitere Typen (Spezialfälle)*: `overlay` (für Docker Swarm), `ipvlan`/`macvlan` (für direkte IP-/MAC-Zuweisung am physischen Adapter), und `none` (komplette Netzwerisolation).

## 4. Docker-Storage (Datenspeicherung)
Da das Dateisystem eines Containers standardmäßig temporär ist und beim Löschen des Containers verloren geht, bietet Docker drei persistente/spezielle Speicheroptionen:

* **Volume**: Wird vollständig von Docker verwaltet (standardmäßig unter `/var/lib/docker/volumes/`). Sicherste Methode, da User ohne Root-/Docker-Rechte keinen Zugriff auf dem Host haben.
* **Bind Mount**: Bindet einen beliebigen, spezifischen Ordner des Host-Pfads direkt in den Container ein. Perfekt für die Entwicklung, da Änderungen auf dem Host sofort im Container aktiv sind.
* **Tmpfs Mount**: Schreibt Daten direkt in den Arbeitsspeicher (Memory) des Hosts statt auf die Disk. Sehr schnell, aber die Daten sind nach dem Stoppen des Containers verloren (nicht persistent). Ideal für sensitive Daten.

## 5. Docker Compose & Microservices
* **Konzept**: Verfolgt den Ansatz einer "Microservices Architecture", bei der eine Anwendung in kleine, lose gekoppelte Services (Container) statt in einen unübersichtlichen Monolithen aufgeteilt wird.
* **Compose-Datei (`docker-compose.yaml`)**: Ein im YAML-Format verfasstes Dokument, mit dem Multi-Container-Anwendungen definiert und mit einem einzigen Befehl (`docker compose up -d`) gestartet werden können.
* **Wichtige Keywords**:
  * `services:`: Definiert die einzelnen Container-Dienste (z. B. Frontend, Backend, Datenbank).
  * `depends_on:`: Steuert die Startreihenfolge (z. B. Backend wartet, bis die Datenbank gestartet ist).
  * `build:`: Baut ein Image direkt aus einem lokalen Dockerfile-Verzeichnis, anstatt ein fertiges Image via `image:` zu ziehen.
  * *Hinweis*: Das `version`-Feld am Anfang der YAML-Datei ist in modernen Versionen (Compose V2) obsolet und wird ignoriert.

## 🧠 Key Takeaways (Die wichtigsten Erkenntnisse)

* **Isolation als Kernprinzip**: Container sind standardmäßig in Bezug auf Prozesse, Netzwerk und Dateisysteme (Mounts) streng vom Host und anderen Containern isoliert.
* **Namensauflösung braucht Custom-Netzwerke**: Wer die Kommunikation zwischen Containern über Namen (statt dynamischer IPs) realisieren will, muss zwingend ein **benutzerdefiniertes Bridge-Netzwerk** (oder Docker Compose) verwenden.
* **Sicherheitsrisiko Docker-Gruppe**: Benutzer in der `docker`-Gruppe besitzen indirekt uneingeschränkte Root-Rechte auf dem Host-System, da der Docker-Daemon als root läuft.
* **Port-Mapping verstehen**: Das Flag `-p 9000:3000` bedeutet immer `Host-Port:Container-Port`. Ohne dieses Mapping ist ein Container-Service von außerhalb des Docker-Netzwerks nicht erreichbar.
* **Saubere Umgebungen halten**: Mit `docker system prune --all --force --volumes` lassen sich ungenutzte Container, Netzwerke, Images und verwaiste Volumes (dangling volumes) effizient aufräumen.
